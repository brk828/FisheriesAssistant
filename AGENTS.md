## 📋 1. Project Context & Philosophy

This project is a **Meta-Agent Framework**. It does not just act as a single chat companion; it acts as an onboarding engineer and traffic controller running locally on a scientist's computer. 

* **The Remote Workflow:** Scientists connect to their office workstation securely via **Tailscale** mesh networks and use **SSH** to interact with a terminal CLI loop (`main_orchestrator.py`).
* **Zero Cloud Lock-in:** The system uses **OpenRouter** as the centralized LLM routing brain (defaulting to Claude Sonnet 4.5, overridable via `OPENROUTER_MODEL`; routine lookups use `OPENROUTER_FAST_MODEL`, default Claude Haiku 4.5, chosen by a local keyword rule in `pick_model`) but executes all actual code, data cleanup, and statistical models locally on the researcher's host machine.
* **Architecture Integrity:** We decouple the **brain** (OpenRouter language parsing and function selection) from the **body** (pre-written Python modules that spin up isolated, validated native R processes).

## 🎯 2. Project Goals

1. **Automated Onboarding:** A script (`setup_onboarding.py`) interviews the scientist, scans their target folder trees, profiles their unique **RProjects**, identifies their coding habits (e.g., Quarto vs. RMarkdown, documentation styles), and drops a localized `project_manifest.yaml` backbone configuration file.
2. **Contextual Awareness:** The master orchestrator reads this manifest on every boot, meaning it knows exactly what projects exist and where files live without hardcoding anything.
3. **Domain-Specific Mastery:** The framework is geared explicitly toward aquatic ecology. It must inherently understand concepts like Gear Types, Catch-Per-Unit-Effort (CPUE), Abundance Matrices, and Mark-Resight tracking arrays.
4. **Self-Updating Knowledge Base:** It houses a prepackaged **Obsidian Vault** (`00_Fisheries_Brain`) split into summary sources and navigational indexes. A background daemon checks an inbox folder for new literature PDFs, reads them, and updates the markdown knowledge base.

## 🛠️ 3. Execution & Language Constraints

When writing or modifying code for this framework, you must strictly follow these structural and division-of-labor rules:

### A. Python's Role (The Framework & Ingestion Layer)
* Python is used exclusively for the main execution loops, file system operations, background cron utilities, YAML manipulation, and interacting with the OpenRouter API.
* **Data Cleaning & Backup:** Python handles pre-analysis routines, text extractions (`pypdf`), file compression, and local directory shifting.
* **No Inline Execution:** Python must never use risky execution paradigms like raw `eval()` or unstructured `subprocess.run(user_input)` to prevent prompt injection or drive-wiping errors.

### B. R's Role (The Scientific Workhorse)
* R is the designated mathematical engine. All specialized analytical agents must write highly optimized, native R scripts to temporary files and run them using Python's subprocess hooks.
* The three built-in agents are **reference implementations and examples, not a limit** on what the framework can analyze:
  1. **`zero_inflated_tmb`:** `glmmTMB` zero-inflated Poisson / negative binomial models for zero-heavy count data.
  2. **`bayesian_nimble`:** `nimble` MCMC state-space models (such as Cormack-Jolly-Seber) for mark-recapture.
  3. **`data_explorer`:** `vegan` and `ggplot2` ordination (PCA, NMDS) and abundance heatmaps.
* **Skills are the way to extend analyses.** For a data type and goal (for example catch-at-age, stock assessment, occupancy, growth curves, survival), the framework finds which analyses the literature uses by searching the brain, then drafts a skill (`icm_skills`) with guidelines, formulas, model structure, diagnostics and the R packages involved. Evidence comes from the brain's references and from the internet (CRAN/package documentation, vignettes, methods papers). Each skill states its sources, keeps brain-derived and web-derived claims distinguishable, and is a draft until the scientist reviews it.
* **Developer-supplied documents (`fisheries_agent/skill_source/`, gitignored):** articles, reports and books the developer places there also feed skills (`python -m utils.skill_source extract|estimate|draft`; specs `icm_templates/source_skills.yaml`, citations `icm_templates/skill_source_refs.yaml`, cited as `[[src:id]]`). Text is extracted locally (OCR for scans); only short excerpts cut locally go to OpenRouter, after an estimate and consent. These are copyrighted: drafts paraphrase and write original code, never store excerpts, and entries marked `local_only` (a licensed book that forbids sharing) are never sent to an LLM. Citations come from the documents themselves; never invent authors.

* **Roles and the skill library:** `fisheries_agent/skill_library/` holds prepackaged Markdown roles (`data-handler`, `analyst`, `synthesist`) and skills, built here in development and copied into each ICM workspace by `utils/skill_library.py` (`.agent/roles/`, `skills/`; content hashes in `.agent/_library.json`, local edits never overwritten, `icm_maintain` reports library updates). Roles are prompts the primary agent adopts (`load_role`, or "@analyst ..."), not separate programs. Skill building happens upstream in this repo; live projects run offline. The data handler writes `data_summary.json/.md` (R script `skill_library/scripts/profile_data.R`, tool `profile_project_data`, CSV and Excel, one entry per sheet; `utils/data_summary.py`/`summarize_project_data` is the CSV-only fallback). The agent finds skills with `list_skills`/`read_skill` (workspace copy first, library fallback) and the system prompt's "New analysis" routine sequences context, skills, profile, plan, approval, run and the analyst reads that, not raw data. Web lookups (`utils/web_evidence.py`: CRAN package check, Crossref methods papers) need consent and are recorded as web-derived. Hand-written library skills are `status: draft` until reviewed; analysis and synthesis skills come from a brain review (see `todo.md`). Python is only for installing the agent and running its own scripts, never for data analysis: analyses are R, run through `utils/runner.py`. The exception is the pipeline engine (`utils/pipeline.py`, `pipeline.yaml` per project, skill `pipeline-orchestration`): Python orders and reruns stale R steps (hash-based), and an optional `kind: refresh` step runs the scientist's own download script only on request. The framework never stores FTP details or credentials; scheduling is a printed `schtasks`/cron line the scientist installs.

## ⚠️ 4. Hard Constraints for Code Generation

* **Context Efficiency:** Do not write scripts that dump massive raw text files into the OpenRouter payload. Ensure folder parsers cap file listings (e.g., max 30 files per project) and PDF readers cap page processing (e.g., max 12 pages) to prevent context window bloat and runaway token costs.
* **Brain Search Is Local and Stub-First:** `search_fisheries_brain` goes through `utils/brain_index.py` (SQLite FTS5 over `02_Brain` concept stubs, then source chunks) and `read_brain_source` reads one source. Never scan the vault file by file per query, and keep results compact. Species aliases and source titles live in `brain_meta/` (built by `utils/brain_enrich.py`); never write derived data into vault files. Hand edits in `brain_meta/aliases.yaml` and `"from": "manual"` titles must always win over generated data.
* **Project Memory Is a Hint:** `utils/project_memory.py` keeps `project_memory/<project>.yaml` (gitignored): notes, key files with short summaries, and recent runs. It is filled by `read_project_file`, `run_project_pipeline`, the model tools and `remember_project_fact`. Always re-check that a remembered path still exists inside the project root, never store raw data or secrets, and keep it free of LLM and network calls. Project questions start with `get_project_context` / `get_latest_results`.
* **ICM Workspaces Are Linked, Not Assumed:** `utils/icm_integration.py` owns the manifest link (`icm_workspace`; `register_workspace` also adds the workspace as its own project) and layered loading (`AGENTS.md` + `CONTEXT.md` always, one stage `CONTEXT.md` only on request). Never load whole workspaces or `data/` files as context. Original projects are never modified by restructure. `refresh_project_references` only writes with `apply=true`, which needs user approval; `run_project_pipeline` asks before running when linked data changed.
* **Citations Come from the Library Sheet:** author, year, title and publication come from the Minckley Library spreadsheet (MID = frontmatter `source_id`), imported with `python -m utils.brain_citations import` into `brain_meta/citations.json` (generated; never hand-edit). Sources from other libraries have no sheet row: `utils/pdf_ingest.py` takes their citation from the PDF itself (DOI -> Crossref, else LLM first-page read verified by Crossref title search, else filename) into `brain_meta/external_citations.json`, keyed by full `source_id` and merged by `brain_citations.load()` (sheet wins on a clash; the sheet import never touches this file). Look citations up with `brain_citations.lookup`, not by MID alone. Never invent an author or year. Literature summaries and reviews route to the main model (`HEAVY_REQUEST`), because the fast model mismatches citations.
* **Non-Minckley PDF Ingest:** `python -m utils.pdf_ingest status|extract|process` handles `00_Fisheries_Brain/pdfs_to_process/*.pdf` (gitignored). Text-layer pages use pypdf; pages with no text are OCRd (Tesseract + Poppler; `TESSERACT_CMD`/`POPPLER_PATH` env vars on Windows), cached in `pdfs_to_process/_extracted/`. `process` shows a token/cost estimate and asks before sending text to OpenRouter (`OPENROUTER_INGEST_MODEL`, default the main model). Notes land in `01_Sources/` with `source_id: "X-<8 hex of file hash>"` (non-numeric, so it never collides with a Minckley MID) plus `title`, `source_citation`, `doi`, `source_file`, `text_extraction`; `brain_meta/ingest_manifest.json` makes reruns skip finished files. After writing a note it updates the stubs for every `[[link]]` (a `Mentioned In` entry plus a short Context excerpt, new stub if none exists; deterministic, no LLM). Stubs are not one file each: `utils/stub_store.py` keeps them as `## Concept` blocks in `02_Brain/Stubs_A.md` ... `Stubs_Z.md` and `Stubs_MISC.md`; always read and write them through `StubStore`, never create per-concept files. Duplicates: same file hash is rejected (PDF removed); same MID/DOI/near-identical title asks skip vs process anyway (non-interactive = skip). Never use a flat chars-per-page guess for scans (real scans ran ~1,300/page, not 3,500). `synthesize_note` wraps the text in `<document>` tags with an instruction after it (sent bare, a scanned proposal/report made the model echo the document tail, failing the section check; hybrid scanner-OCR PDFs 17697/19654 hit this, OCR itself was fine) and its failure message quotes the start of the reply. ## Current PDF ingestion behavior
- `utils/pdf_ingest.py` defaults PDF note generation to `anthropic/claude-haiku-5.5`; `OPENROUTER_INGEST_MODEL` explicitly overrides it. The main orchestrator still uses `OPENROUTER_MODEL`.
- A PDF is automatically skipped as a duplicate only when its Minckley ID is already represented in the library. Similar titles/DOIs and matching file hashes do not block processing.
- Notes are capped at 250,000 characters by default. For longer PDFs, the user may choose full text (up to 450,000 characters) or skip; no response within 10 seconds selects the 250,000-character cap.
- Processing still requires the normal estimate/consent; stub-store consolidation, OCR/extraction failures, model/API failures, and the optional post-run Git sync prompt can also stop or pause a batch. Successful PDFs are removed from `pdfs_to_process` by default.
- Per-document request usage is appended to the Git-ignored `fisheries_agent/runs/pdf_ingest_usage.jsonl`. It records metadata and OpenRouter cost, not prompts or document text; generation IDs are retained for cost reconciliation if a response omitted `usage.cost`.

## Minckley Library reference
- Minckley PDFs live in `C:/Obsidian/Fish_Science_Brain/MinckleyLibrary` (renamed from `PDFs_To_Process` on 2026-11-10, matching `MarshLibrary`; default of `MINCKLEY_PDF_DIR` in `minckley_lists.py` and `minckley_batch.py`). Not to be confused with the repo's `00_Fisheries_Brain/pdfs_to_process/` inbox.
- `brain_meta/minckley_library.csv` is the reference for Minckley citations (11,264 rows; built from the curated `00_Fisheries_Brain/MinckleyLibrary.xlsx`). `brain_citations` reads it instead of the old Google sheet.
- Rebuild after editing the Excel file: `python -m utils.minckley_reference build` then `python -m utils.brain_citations import`. The conservative spell check logs each change to `brain_meta/minckley_spellfix_log.csv`; it skips names, taxa and non-English words.
- 27 MIDs appear on more than one row (127 rows; listed in `brain_meta/minckley_duplicate_mids.csv`). The importer keeps one row per MID, so these need review.
- **Website PDF links:** `site/scripts/build-data.mjs` reads `permission` in `brain_meta/minckley_library.csv`; Minckley notes marked `public domain` get a link to `https://www.marsheducation.org/library/textpdf/<MID>.pdf` at the top of their page (others keep the request-a-PDF text). `site/scripts/verify-pdfs.mjs` (runs in `npm run build`, or `npm run verify-pdfs [-- --strict]`) HEAD-checks every such PDF and records 404s in `site/pdf-missing.json` (committed; those pages drop the link). Network errors never mark a PDF missing. Applies only to Minckley-processed items. Delete entries from `pdf-missing.json` when the PDF is later uploaded to that site.
